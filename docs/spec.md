Webサービス仕様書：PlayCastr (.net)

1. サービス概要
   サービス名: PlayCastr (プレイキャスター)

コンセプト: ストリーマー（配信者）が「今、どのゲームをプレイすればリスナー（視聴者）を集められるか」をデータに基づきリアルタイムに可視化・提案するダッシュボードツール。

ターゲット: 個人ストリーマー（Twitch / YouTube Live等で活動する配信者、およびこれから始める層）

コア価値: 視聴者が多いのに配信ライバルが少ない「ブルーオーシャン（穴場）ゲーム」を可視化し、新規リスナーの獲得（初見さんホイホイ）を支援する。

2. システムアーキテクチャ（推奨）
   フロントエンド: Next.js (App Router), Tailwind CSS, Lucide React (アイコン)

バックエンド: Next.js API Routes (Route Handlers)

データベース: Supabase (PostgreSQL) または SQLite (初期プロトタイプ用)

外部API連携: Twitch API (New Helix), Steam Web API (フェーズ2以降)

3. 主要機能一覧（フェーズ1：MVP）
   📱 フロントエンド（画面機能）
   メインダッシュボード画面

穴場ゲームランキング (コア機能): 「穴場度スコア」が高い順にゲームをカード型/リスト型で表示。

表示項目: ゲームタイトル、ゲーム画像、総視聴者数、総チャンネル数、穴場度スコア、配信カテゴリタグ（例：参加型向き、リアクション重視、インディー）。

ソート・検索フィルター: スコア順、視聴者数順、ゲームタイトル検索、タグ絞り込み。

ゲーム詳細ポップアップ/モーダル

該当ゲームの直近の推移、公式配信ガイドラインへのリンク、おすすめの配信時間帯などの簡易表示。

⚙️ バックエンド（データ処理機能）
外部データクローリング (Cronバッチ処理)

定期的に（例：30分〜1時間に1回）Twitch APIを叩き、全アクティブゲームの「現在の視聴者数（viewer_count）」と「配信チャンネル数」を取得。

穴場度スコア算出ロジック$穴場度スコア = \frac{総視聴者数}{総配信チャンネル数}$ をベースに計算（※配信者が0のバグを防ぐバリデーションを含む）。

データベース同期

計算結果をデータベースに保存。フロントエンドはAPIを直接叩かず、このデータベースの値を読み込むことで表示を高速化し、API制限を回避する。

5. デザイン・UI/UXガイドライン
   トーン＆マナー: ダークモード（Dark/Slate系）を基調とし、アクセントカラーにストリーマー好みのネオンカラー（パープルやシアンなど）を採用した、サイバーかつクリーンなガジェット風デザイン。

フォント: Sans-serif (Interなどの視認性の高いモダンフォント)

レスポンシブ: PCでの閲覧をメインとしつつ、スマホから「今日の配信何にしよう」と布団の中でチェックできるレスポンシブ対応。
